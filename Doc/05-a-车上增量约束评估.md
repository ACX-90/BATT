## 一句话

## 背景：三条硬限制

1. **不随便 OTA。** 不能把增量理解成「远端算好 \(k_0,k_1\) 或残差头，再发到车上」。出厂烧进去的舰队表可以有；日常改表必须车内自己完成、自己写回NVM。召回式刷写不是增量通道。
2. **MCU 数据不能随便外发。** 不能把 \(I,T,U,s\) 波形打包到云端跑 `increment.py`。设计必须在**上行 = 0** 时也能工作。以后若允许上报几个乘子做监视，那是诊断，不是训练数据。
3. **整套 BMS 堆在一颗 MCU。** 保护、均衡、绝缘、通信、SOC 显示先占资源。算法拿到的是剩下来的配额，不是芯片手册上的整片 SRAM / Flash。`Doc/A0-a` 的 TC4D7「很空」是**芯片上限**；本文用的是**算法配额下限**。两套不要混。

三条合在一起：车上几乎没有旧样本，也没有远端批次，只能用当前这一趟（或刚过去的一个短窗）去改**很少几个数**。外置 Flash 若加，也只是车内多一块盘，不改变「不外发、不 OTA」；它能不能把回开放回来，下一节单独评。

## 第 0 期哪些结论还在，哪些上不了车

| 第 0 期结论 | 实验室 / 下线 | 车上（本背景） |
|-------------|---------------|----------------|
| 同分布冻结 | 正途 | **正途**，零成本 |
| 整体涨阻走 \(k_0,k_1\) | 正途 | **正途**，每芯 2 个数，可上车 |
| 一趟表偏走 \(\delta R_0\) | 正途 | **正途**，滤波里跟，不改曲面 |
| 缺温区走 Replay / 重训 | 正途 | **做不到**：没有旧网格；外置 Flash 也补不出没见过的温区特征 |
| 合集重训、只微调整张网 | 对照档 | **做不到**：要存旧轨迹、要反传几千个数 |
| 门控：无边沿 / 零偏 / 容量错不拆 \(R\) | 仍要 | **更要**。车上没有事后人工看曲线 |
| 64×64 学 BOL 曲面 | 舰队预训练 | 只当**冻住的推理表**出厂烧入，车上不训 |

填洞不是「换个算法就能在 MCU 上做」。冻前层时 18 个数补不出新温度特征（`Doc/03-d`）；解冻前层又没有 Replay。车上碰到没覆盖的温区，正确动作是**不更新**，不是硬增量。

## 资源信封（算法配额，待项目替换数字）

没有锁定料号之前，先用一档**故意偏紧**的信封。第 1 期新模块必须能塞进去；项目给出真实配额后再改数字，不改结构。

按大约 180 串高压包、SoX 环 0.1 s 估：

| 资源 | 算法建议上限 | 为什么是这个量级 |
|------|--------------|------------------|
| Flash / ROM | 冻结舰队表一份 ≤ 20 KB；增量代码几 KB；每芯可变参数合计 ≤ 20 KB | 保护和应用先占 Flash。64×64 方案 B 约 18 KB，已经接近这份上限 |
| RAM（稳态） | ≤ 16～32 KB | 均衡表、通信缓冲、EKF 状态先在。不能按轨迹攒波形 |
| RAM（更新瞬间） | 峰值仍 ≤ 32～64 KB | 不许为一次反传申请数 MB 激活 |
| CPU | 0.1 s 环里前向 + EKF 全包不超过核的一成左右；反传不进保护环，且远低于 10 Hz | 学习必须可关断 |
| NVM写回 | 每芯几个 float，掉电还在 | 不能等下一次 OTA 把表带回来 |

对照现有几档的体积：

| 对象 | 体积（float32） | 180 芯 | 车上 |
|------|-----------------|--------|------|
| 舰队 64×64 | ≈ 18 KB 一份 | 一份共享 | 只推理，冻住 |
| \(k_0,k_1\) | 8 B / 芯 | ≈ 1.4 KB | **默认可变集** |
| \(\delta R_0\) | 4 B / 芯（可进 EKF） | ≈ 0.7 KB | 滤波层，默认可开 |
| 3×8×2 后层 | 72 B / 芯 + 前层 128 B 共享 | ≈ 13 KB | 可选；纯涨阻不该赢 \(k\) |
| 一条 10 min 网格轨迹 | 6200 步 × 数列 ≈ 120 KB | 100 条 ≈ 12 MB | 片上 RAM **存不下**；16 MB 外置 NOR 勉强能放下舰队，见下文 |
| 整段 BPTT 激活（64 宽） | 单条已是 MB 级 | — | **禁止** |
| Adam 一阶二阶矩 | 参数量 ×2 | 头已约 26 KB，宽网更大 | 车上用 **SGD / 累积梯度**，不用 Adam |

CPU 上，180 芯 × 10 Hz 的 64×64 前向大约 \(10^7\) 次乘加/秒。核还剩一成给算法时，这已经是大头。第 1 期要量一次：超了就改查找表推理，**不要**据此去车上训宽网。3×8×2 前向可以忽略；贵的是宽网前向和「误把反传塞进 0.1 s」。

`Doc/A0-b` 写过：S32K37 这一档 800 KB SRAM 上，若还要攒门控轨迹做 Replay，会先碰到墙。本背景比那更紧——SRAM 不是算法私有的。

## 约束推出来的设计规则

这些不是实现细节，是第 1 期不许违反的。

**1. 车内自洽，不靠云。**  
出厂：一份冻结 \(f_{\mathrm{fleet}}\)（宽网或由表压缩的查找表）+ 每芯 \(k=1\)（头为 0）。  
运行：只改每芯那几个数，写回片上NVM。  
没有「停车上传、云端 Replay、OTA 写回」这条路径。

**2. 可变参数必须少，而且每芯一份。**  
车上默认写 \((s,T)\) 上的 \(k\) 网格（1b）：当前窗只动被点到的节点。全局 \(k_0,k_1\)（1a）是 1×1 的网格，留给实验室对照，或若干温区节点已经齐了之后的加速，**不要**靠分类器在更新前猜「整张还是局部」。不要先上 18 个数的残差头。  
不要在车上解冻 64×64，也不要每芯复制一份宽网。

**3. RAM 不存波形，只累加。**  
滑窗是协议，不是片上缓冲区。窗内把开环误差合成一个梯度，窗口结束走一步。RAM 跟参数走，不跟窗长 × 串数走。  
「有没有边沿 / 回弹」用几个标量记（最大 \(|\Delta I|\)、静置时长）。外置 Flash 若有，只许存门控事件，不许把 0.1 s 环变成写盘环，见下一节。

**4. 反传降频，离开 0.1 s 保护环。**  
EKF + 冻结表前向可以 10 Hz。改 \(k\) 或头：有激励才允许，且 ≤ 1 Hz 或一次充电结束一次。持续超限不得每 0.1 s 一步（`Doc/03-d` 的洗头病，车上更没人救）。

**5. 损失仍是开环 \(e^{\mathrm{ol}}\)，SOC 仍用安时。**  
滤波后验残差不当损失。没有云端人工看 NIS，门控必须在车上自己挡：电流太小、无边沿、全包同向先查分流器 / 容量，不拆电阻。

**6. 优化器要无状态。**  
SGD 或窗内累积梯度。Adam / 逐参数学习率在 MCU 上既占 RAM，又难认证。学习率写死，\(k\) 和 \(\Delta R\) 有界，异常则退回 \(k=1\) / 头清零。保护链只读 AFE，不读 \(\hat U_t\)。

**7. 填洞和下线标定分开。**  
没去过的温区，节点保持 \(k=1\)，不要用别的温区去猜。车后来真的开到该温区，只动附近节点（\(k\) 网格的局部性，见下文）。解冻宽网、换化学体系、OCV 重标仍是实验室 / 产线。

## 车上还剩哪几档

按约束筛过以后，车上增量只剩这张菜单。第 1 期只许在这里面设计。

```
开环电压相对舰队底板
        │
        ├─ 几乎没高 / 无边沿 / 无回弹 → 冻结（什么都不写）
        ├─ 全包同向、安时在漂         → 先查电流零偏 / 容量，不动 k
        ├─ 只有这一趟边沿大           → δR0；连续多天同号再写 k
        └─ 连续多天同号、有激励       → 写当前窗点到的 k 网格顶点（默认 1b）
              没去过的节点保持 k=1
              全局 vs 局部事后从节点读，不在更新前猜
              1a（1×1）只当节点已齐之后的加速档
```

单窗落在当前 \((s,T)\)，分不出「各温区同号」还是「只这一区大」。先走 1a 再切 1b，中温已经被全局 \(k\) 抬过。网格自己带隔离：整张涨阻会把去过的节点齐刷到约 1.15；只冷端错则中温保持 1。用法见 [`Doc/04-b`](04-b-增量学习应用手册.md) §2.3。

第 0 期的 Replay / 合集重训 / 只微调整网，从第 1 期起只当**实验室对照**，不当车上默认方案。外置 Flash 不能把「实验室 Replay」原样搬上车，下一节说能搬哪一层。

和英飞凌 demo 的差别仍然成立，而且被约束加强了：他们按拍反传 18 个数，是「没回放时的展台折中」。我们车上默认同样没回放，所以更要滑窗、门控、先 \(k\) 后头，而不是把 demo 的 10 mV / 0.1 s 原样搬进来。

## 外置 Flash 存轨迹：能补什么，补不了什么

片上 RAM 存不下轨迹，是前面说 Replay 上不了车的直接原因。有人会加一颗 SPI NOR / NAND，把波形放到 MCU 外面。下面按**还是不 OTA、还不外发、RAM / CPU 信封不变**来评。加盘不等于换了一台工控机。

### 能放下多少

一条本仓库网格轨迹（约 10 min、6200 步、电流 / 温度 / SOC / 电压）大约 **120 KB**。100 条舰队约 **12 MB**。180 串若各存一条 10 分钟，大约 **20 MB**。

| 介质（车规常见） | 容量量级 | 当轨迹盘 |
|------------------|----------|----------|
| 片上 DFLASH / EEPROM | 几十～几百 KB | 只够 \(k\) / 头，不够波形 |
| SPI NOR 8～32 MB | 正好一档 | 能放下若干门控窗，或勉强一份舰队网格 |
| SPI NAND / eMMC ≥ 128 MB | 大 | 连续记行程也够，但 FTL、ECC、坏块都要软件 |

**不能全程 10 Hz 记。** 包电流 + 180 芯电压大约每小时二十多 MB。NOR 擦写次数只有大约 \(10^4\sim10^5\)，几天就能把盘写废。必须**过门控才落盘**：有边沿或回弹的 5～20 s 窗。一个 20 s 窗（200 拍）若存共享电流 + 每芯开环误差，大约 0.3 MB；16 MB NOR 大约能转 **50 圈**这种窗。这已经是「几天到几周的激励样本环」，不是行车记录仪。

读可以在停车后从 QSPI 流进来，带宽够。写不能进 0.1 s 保护环，要另缓冲、另任务。

### 仍然过不了的墙

外置 Flash 只存**输入波形**，不存反传激活。RAM / CPU 信封没变。

| 想做的事 | 有外置 Flash 之后 |
|----------|-------------------|
| \(k_0,k_1\) 混几天前的脉冲再走一步 | **值得做。** 流式读窗、SGD，RAM 仍只有两个数。减轻「这一趟 SOC 窗口把 \(k\) 拧歪」 |
| 18 个数的头混旧窗（冻前层） | **值得做。** 这是车上版 Replay-lite，专门打 demo 那种相关样本洗头。仍补不出第 9 个温度特征 |
| 回放 `Data/grid/` 那种 100 条、解冻 64×64 | **仍做不到。** 单条整段 BPTT 激活就是 MB 级；截断 50 步也只够逐芯、停车长算，第 1 期不立项 |
| 缺温区填洞（任务 B） | **仍做不到。** 盘里若没有 −10 °C，回放的是旧的 25 °C，和没盘一样；即便后来开到 −10 °C，冻前层也长不出新方向 |
| 云端 `increment.py` 再 OTA | **仍然禁止。** 数据在车内盘上，不等于可以外发 |

所以：Flash 把「完全没有旧样本」变成「有一个门控事件环」。它救的是**小参数集的遗忘**，不是舰队曲面、不是填洞、不是宽网重训。

### 额外代价（不只是多一颗料）

- **BOM / 管脚 / 认证**：QSPI 占用、布局、车规料、ECC。学习数据在 QM 分区，坏盘或写坏不得影响保护。
- **磨损与掉电**：只写门控窗、磨损均衡、写完校验；异常则丢掉这个窗，不要写坏 \(k\)。
- **数据在盘上**：仍然不外发。但维修能把 Flash 拆走，等于车内多了一份波形。策略上要当「可被取证的残差日志」看，不要当黑匣子乱记 SOC 以外的隐私字段——本仓库这段本来就只该有 \(I,T,s,U\)。
- **CPU**：回放放在停车或充电结束。日常 0.1 s 环仍然只做 EKF + 冻结表前向。

### 怎么用（若 BOM 允许）

默认第 1 期**不依赖**这颗料。没有外置 Flash，就按上文：窗内累加、只动 \(k\)。

若有 16 MB 这一档：

1. 只落盘过门控的短窗（边沿 / 回弹），环形覆盖。
2. 更新 \(k\) 或头时，从环里抽几段旧窗 + 本段新窗，流式 SGD。
3. 电流共享，不要 180 份完整轨迹各拷一遍。
4. 舰队 64×64 仍冻在 MCU ROM / 片内，不进这颗盘来回训。
5. 盘不是上行通道。

结论：**外置 Flash 值得作为可选项，用来给 \(k\) 网格做防遗忘环；不值得当成「车上 Replay 宽网」的许可证。** 第 1 期对照仍先跑无盘路径；有盘再加一档「事件环混旧窗」。\(k\) 网格本身已经按节点隔开温区，Flash 不是填洞的前提。

## 候选结构：冻住的共享表 + 每芯 \((s,T)\) 上的 \(k\) 网格

这是信封里比较靠谱的下一档，全局两个乘子的直接加宽，不是再抄 3×8×2。

### 在做什么

```
(I, s, T) ──► 冻结的共享表 f_fleet ──► (R0, R1)
s, T      ──► 该芯 k 网格，邻点插值 ──► (k0, k1)
                                      │
                    R0' = k0 R0 ， R1' = k1 R1
```

- **共享表**：车队 64×64 可以先冻着推理；MCU 紧了再压成更小的网，或直接烤成 \((I,s,T)\) 查找表。出厂烧入，车上不训。
- **每芯一份 \(k(s,T)\)**：几十个节点，每个节点两个正数 \(k_0,k_1\)，默认 1。当前 \((s,T)\) 找最近几个节点，双线性插值得到这一拍的乘子。
- **增量只改被点到的节点。** 开环电压误差经插值权重回到 2～4 个顶点。没去过的格子保持 1，等于结构上的 Replay：25 °C 的节点不会被 −10 °C 的梯度洗掉。

乘性校正对着第 0 期 A / G 的老化（整张 ×1.15、寿命因子）。加性 \(\Delta R\) 要另夹正性，这里不必。

### 为什么比 18 个数的头更贴车上

| | 全局 \(k_0,k_1\) | \((s,T)\) 上的 \(k\) 网格 | 3×8×2 残差头 |
|--|------------------|---------------------------|--------------|
| 每芯可变 | 2 | 几十 × 2（节点数可控） | 18，且绑在 8 个冻死的特征上 |
| 遗忘 | 一处涨、处处涨 | 只动附近节点 | 18 个数全体工况共用，会洗头 |
| 填洞（车后来开到该温区） | 会把中温一起抬 | 只抬该温区节点 | 冻前层补不出第 9 个方向 |
| 可解释 / 有界 | 最好 | 好，可画 \(k(s,T)\) 图 | 差 |
| 乘加 | 两次 | 插值几次 | 50 次，仍便宜 |
| \(I\) 维残差 | 无 | 无（留给共享表） | 形式上有，8 个特征未必学到 |

任务 A 那种整张涨阻，网格会学成「所有节点都约 1.15」，**事后**可以当成全局 \(k\)，不是更新前先判 1a。只冷端错：车只要真的在 −10 °C 有边沿，只动冷端节点，中温不用回放旧轨迹。这和第 0 期「填洞必须 Replay 宽网」不矛盾——那是解冻同一张曲面时才必须；**把可变部分按 \((s,T)\) 切开之后，局部乘子自己带隔离。**

### 放多少点、占多少空间

节点位置出厂写死，车上只改数值，不要运行时增删节点。均匀网格最好实现；要加密，在标定时装密，别在车上自适应长点。

建议先密两端 SOC、密低温（Arrhenius 陡、U 形两端），中间稀一点。例如 SOC 10 / 30 / 50 / 70 / 90% × 温度 −10 / 10 / 30 / 50 °C = **20 个节点**。

| 网格 | 每芯 float32 | 180 芯 | 合不合 05-a 信封 |
|------|--------------|--------|------------------|
| 1×1（全局 \(k\)） | 8 B | 1.4 KB | 默认可变集 |
| 5×4（20 点） | 160 B | 29 KB | 略超 20 KB；改 int16 约 14 KB，能塞 |
| 「几十个点」（如 6×5=30） | 240 B | 43 KB | 偏满，先别用 |

插值本身可以忽略。共享表实测见 `Doc/05-c` §9：三维 9×11×9 查找表 7 KB、全网格 4.56 mV，贴地板；蒸馏 16×16 约 9 mV；纯 \((s,T)\) 二维不行（缺电流维）。压缩误差必须明显小于 1C 上 15% 电阻那堵约 22 mV 的墙。

### 必须守的几条

1. **\(k\) 不要吃电流维。** \(I\) 的饱和、充放不对称留给共享表。残差真的随 \(I\) 变，再单独立项，不要把网格变成 \((I,s,T)\) 三维——点数会爆。
2. **乘性、为正。** \(k=\exp(\cdot)\) 或 softplus，夹在例如 \(0.5\sim 2\)。节点初值 1。
3. **邻点要光滑。** 只更新插值权重大的顶点，并加一点邻格差的罚，否则 \(k\) 会棋盘格，插值乱抖。
4. **门控不变。** 静置看不见 \(R\)，不更新；无边沿不拆 \(R_0/R_1\)；全包同向先查分流器。否则每个路过的节点都会把零偏写成假内阻。
5. **没去过的格子保持 1。** 不要用外推把没见过的 −20 °C 写成旁边 −10 °C 的 \(k\)。
6. **压缩共享表和 \(k\) 网格是两件事。** 64×64 前向已经超一成核（`Doc/05-c`），冻结表改三维查找表；增量仍只动每芯 \(k\)。不要两件一次做，分不清是插值损了还是 \(k\) 没学到。

### 不靠谱的部分（别预期过高）

- 格子比激励还密，等于没激励的节点乱飘。几十个点已经够用，不要上百。
- 共享表在某温区形状都错了（不是幅度错），局部 \(k\) 只能把错误的 \(R(s)\) 整体加减，补不了一段鼓包的形状。那是换表，不是加密网格。
- 仍不是实验室 Replay：不能靠盘里的旧 25 °C 去「教会」共享表一个新的 Arrhenius。只能在**这只电芯、这个 \((s,T)\)** 上乘一个数。

## 第 1 期怎么验（已跑，数字 [`Doc/05-d`](05-d-车上增量精度评估.md)）

不写 MCU C，但 PC 对照必须**假装自己是那颗缺资源的 MCU**：

| 验收 | 通过 |
|------|------|
| 更新时读不到 `Data/grid/` 旧集 | 无 Replay 仍能做 A / D / G 的缩放 |
| 可变参数先每芯 2 个，再 \((s,T)\) 网格 | 涨阻时各节点 \(k\) 应齐；只冷端错时只动冷端节点 |
| 窗内不存整段波形 | 梯度累积与存波形数值同量级即可 |
| 无边沿新年份 | 不更新，或只报 \(R_0+R_1\) |
| 优化器 | SGD；无 Adam 状态 |
| 内存记账 | 给出 ROM / RAM / 每窗乘加，对照上文信封 |
| 填洞任务 B | 允许失败并标成「车上不做」；不要为了 B 去解冻宽网 |
| 外置 Flash（可选） | 默认不依赖；有则只测门控事件环混旧窗，不许据此解冻 64×64 |

数字基线仍用第 0 期：100 轮底板 7.8 / 11.8 mV，500～2000+ 轮地板 5～4 mV，1C 上约 40～50 µΩ。车上增量的目标不是把底板再压 1 mV，而是在信封里把 \(I\Delta R\) 那堵墙收掉。

## 和 A0 文档的关系

`Doc/A0-a` / `A0-b` 问的是：TC4D7 / P3E / S32K 这类芯片**能不能塞下** demo。结论是算力往往空，先破的是共用电流、静置误触发、学习与保护没切开。

本文问的是另一件事：在**不 OTA、不外发、配额只是一颗忙 MCU 的边角**时，增量算法还许做什么。即便以后换到带 PPU 的大芯片，本项目的增量默认仍按紧信封设计——宽了再放松配额，不许一上来按 10 MB SRAM 去攒轨迹。

仍不做：MCU 固件、把学习写进保护核、车上解冻前层、用 NPU 做 18 个数的 SGD。

其它还可能的增量路子见 [`Doc/05-b`](05-b-车上增量方案头脑风暴.md)。TC4D7 上怎么测周期和负载见 [`Doc/05-c`](05-c-TC4D7资源与负载评估.md)、[`Src/MCU_Eval/`](../Src/MCU_Eval/readme.md)。第 1 期精度见 [`Doc/05-d`](05-d-车上增量精度评估.md)，可分享读法 [`Doc/05-e`](05-e-第1期实验汇报.md)：默认写 \(k\) 网格，1c 丢掉。
